# Human UI Copy Protocol

Avoid complex grammar, corporate jargon, and unnecessary technical words (e.g., "Initiate", "Execute", "Authenticate", "Configure", "Runway", "Allocation", "Distribution") when writing UI text, button labels, or user-facing instructions.

We build for everyday humans, not compliance manuals or corporate memos. Copy should feel approachable, direct, and effortless to scan.

## Guidelines

1. **Use Plain English**: Choose the simplest, most common word available (e.g., "Transfer" instead of "Initiate Transfer"; "Sign in" instead of "Authenticate"; "Save" instead of "Persist"; "Strict lock" instead of "Immutable allocation").
2. **Keep It Conversational**: Write as if speaking to a real person. Never sound like a dictionary, legal contract, or pitch deck.
3. **No Redundancy**: If one or two words do the job cleanly, do not pad labels to sound formal.
4. **Honest & Specific**: Replace vague hype with plain facts. Every example figure or claim on screen must match the actual rule being described.
5. **Ruthlessly Edit**: Before finalizing any UI copy, read it aloud and ask: *"Is there a simpler, shorter way to say this?"* If yes, rewrite it.
